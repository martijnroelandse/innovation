01 / STRESS-TEST A TOOL

Choose the tool. Keep the answers independent.

Start with eight authored controls: four for manuscript comparison and four for numerical checking. Each has a specific expected response. A tool is assessed only where it returns an answer; missing responses stay unknown.

Baseline / first tool

Run a local tool or import your first result.

Candidate / upgrade or additional tool

Use the same test set. Versions can be compared only on jointly assessed cases.

Import format and evaluation limits +

Run a supplier’s tool separately with permission, then map its output to the exact criterion for each case. This prototype has no direct supplier API connections. These eight controls are narrow examples, not a suitable benchmark for every listed product. Unsupported criteria should return null or be omitted. The report’s tool field must match the selected tool; tool names and supplied outputs are not authenticated.

true = defined change/problem flagged; false = assessed and not flagged; null or omitted = unassessed. Expected labels remain in RefleX and are excluded from the input download. Files stay in this browser.

Use representative validation results when you have them. Until then, vary explicit assumptions for your submission population. The small control set above does not supply production error rates.

Scenario only. One binary target issue, one review per unique alerted submission, constant performance and equal review time. Counts are expected values. No financial cost is assigned to missed issues. Stack performance must be validated as a stack; individual rates cannot simply be added.
